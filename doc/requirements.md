# アルバイト口コミWebアプリ 要件定義

更新日: 2026-09-23

本書は現在のMVP要件を定義します。実装済みかどうかは[実装状況](./implementation-status.md)、将来候補は本書の「将来スコープ」で区別します。

## 1. サービスコンセプト

求人票だけでは分からない職場の雰囲気、人間関係、新人教育、忙しさ、シフトの相談しやすさを、アルバイト経験者の口コミで可視化します。点数だけで順位を決めるのではなく、投稿者の背景と生の声を一緒に示し、求職者が自分で判断できる材料を提供します。

## 2. 対象ユーザー

| 区分 | 現在の用途 |
| --- | --- |
| 求職者 | 店舗検索、口コミ閲覧、「気になる」保存 |
| 投稿者 | 開発環境での口コミ入力・公開プレビュー |
| 開発・運用担当 | 開発DBのseed、投稿確認、限定リセット、開発デモ運用 |

企業ユーザー、管理者画面、一般ユーザー認証は将来スコープです。

## 3. 現在のMVP要件

| 機能 | 要件 | 状態 |
| --- | --- | --- |
| 店舗検索 | 店舗名、エリア、業種、最低評価、並べ替え、ページング | 実装済み |
| 店舗詳細 | 基本情報、4評価軸、口コミ、投稿者背景、特徴タグ | 実装済み |
| 候補保存 | 店舗IDだけをブラウザへ最大100件保存 | 実装済み |
| 口コミ投稿 | 5ステップ、30〜300文字の生の声、プレビュー、同意 | 開発環境限定で実装済み |
| リアクション | 参考になった／ありがとう／役に立った | 開発環境限定で実装済み |
| 認証・認可 | 本人確認、Session、所有者・組織権限 | 未実装 |
| CI / 配備 | 自動検証、最新 `main` の開発デモ反映 | 実装済み |

## 4. 口コミ投稿要件

- 在籍状況、勤務当時の立場、勤務期間を必須にする。
- 雰囲気とスタッフ層は許可された選択肢から各1〜2件、店長の関与度は1件選ぶ。
- 4つの評価を1〜5の整数で入力し、おすすめ度を別に回答する。
- 生の声は前後の空白を除いたUnicodeコードポイント単位で30〜300文字とする。
- 生の声には設問、補足、書き方のヒント、常設の記入例を表示する。
- 最終送信時にもサーバー側で全項目、選択肢、文字数、同意、ガイドライン版を検証する。
- `userId`、総合点、同意日時をクライアント入力として信用しない。
- 投稿者ID、正確な投稿日、同意日時を公開しない。

## 5. 評価と比較

- 評価軸は職場の雰囲気、教育・フォロー体制、業務のゆとり、シフトの融通度とする。
- 口コミ総合点は4評価の算術平均とし、おすすめ度を含めない。
- 店舗の評価軸別・総合点は、勤続期間と在籍状況を掛け合わせた重み付き平均とする。
- 店舗の評価順は、口コミが少ない店舗を全体平均へ寄せるベイズ補正値を使用する。表示と最低評価の絞り込みには重み付き総合点を使用する。
- 店舗集計値は小数第1位へ丸めて保存する。
- 旧プロトタイプの重視項目による並べ替えと、口コミ単位の参考度表示は現在の要件に含めない。

## 6. 非機能・セキュリティ要件

- スマートフォンを含むレスポンシブ表示とキーボード操作に対応する。
- 検索、投稿、リアクションの入力をZodで検証し、DB制約でも整合性を守る。
- SQLはパラメータ化し、自由記述をHTMLとして解釈しない。
- 公開レスポンスを表示に必要な情報へ限定する。
- 投稿とリアクションは、認証導入まで開発環境・明示フラグ・ローカル開発DBの一致をサーバー側で要求する。
- 内部エラー、stack trace、接続情報、トークン、認証情報を利用者へ返したりログへ残したりしない。
- デプロイ前にDBをバックアップし、失敗時に直前のコードへ戻せるようにする。

## 7. AI活用の位置づけ

現在のMVPは外部AI APIを呼び出しません。検索は明示的な条件、評価はコードで定義した重みと算術平均で処理し、候補の保存と最終判断は利用者が行います。

将来、口コミ要約や自然言語検索を検討する場合も、AI出力を原文の代わりにせず、元口コミを確認できる補助情報とします。AI出力からDB更新、通知、応募等の外部操作を自動実行しません。

## 8. 将来スコープ

- 一般ユーザー認証、Session、所有者・組織単位の認可
- プロフィール、投稿履歴、口コミ編集・削除、通報
- 企業向け店舗分析・集計画面
- お気に入りのアカウント保存と端末間同期
- 自然言語検索、口コミ要約、Embedding、レコメンド
- E2Eテストと認証・認可の攻撃的テスト

ネイティブアプリ、DM、求人応募・採用管理、決済、口コミ画像投稿、本格RAGは現在の対象外です。

## 9. 成功条件

- 求職者が、求人票だけでは分からない働き方を4評価軸と実体験から想像できる。
- 投稿者が、何を書けばよいか迷わず、公開内容を確認してから送信できる。
- 少数口コミでの属性表示、日付の曖昧化、公開情報の限定によって不要な特定リスクを下げる。
- 自動計算の定義、公開条件、環境制限がコード・テスト・文書で一致している。
- AIや単一の平均点に判断を委ねず、利用者が比較材料を確認して候補を決められる。
