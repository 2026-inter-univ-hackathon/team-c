# アルバイト口コミWebアプリ 要件定義

本書は目標とする仕様・構成を含みます。現在の実装範囲と未実装機能は[実装状況](./implementation-status.md)を参照してください。

## 1. サービスコンセプト

求人票だけでは分からない**職場のリアル**（雰囲気・人間関係・新人教育・忙しさ等）を、アルバイト経験者の口コミで可視化する。企業側には口コミを集計して職場改善に活かしてもらう。

## 2. 解決したい課題

| 立場 | 課題 |
|---|---|
| 求職者 | 時給・勤務地等の条件は分かるが、職場の雰囲気や暗黙のルールが分からず「入ってみたら違った」が起きる |
| 企業 | 複数店舗の職場環境（人間関係・業務負荷等）を数値だけでは把握しづらい |

## 3. ユーザー区分

| 区分 | 主な用途 |
|---|---|
| **一般ユーザー**（高校生・大学生中心） | 店舗検索、口コミ閲覧・投稿 |
| **企業ユーザー**（店舗責任者・採用担当等） | 自社店舗の評価・課題の把握 |
| **管理者** | 不適切投稿対応、ユーザー・店舗管理（MVPでは最小限） |

## 4. 主要機能一覧

| 機能 | 概要 | MVP優先度 |
|---|---|---|
| 認証・認可 | 開発中はBasic認証＋固定テストユーザーで動作確認。将来はGoogle OAuth等へ交換可能にする | 必須 |
| 店舗検索 | 店舗名・業種・エリア・評価等で検索。将来的に自然文検索 | 高（自然文検索は技術チャレンジ） |
| 店舗一覧・詳細 | 基本情報、評価、口コミ一覧の表示 | 必須 |
| 口コミ閲覧 | 総合評価だけでなく実際の仕事内容・雰囲気を伝える | 必須 |
| 口コミ投稿 | 勤務情報＋5段階評価＋自由記述の質問に回答 | 必須 |
| プロフィール | 投稿履歴・投稿数の表示（将来レベル制導入も想定） | 高 |
| 企業ダッシュボード | 管理店舗一覧、評価集計、店舗間比較 | 高 |
| 口コミ分析（AI） | 良い点・改善候補の自動要約 | 技術チャレンジ（簡易実装可） |
| レコメンド | 類似店舗の推薦 | MVP対象外 |

### 口コミ投稿の質問設計（差別化ポイント）
単なる自由記述ではなく、実体験を引き出す質問を用意する：
- 新人が最初にぶつかる「初見殺しトラップ」は？
- ミスしたとき、周りはどんな反応？
- 一番忙しくなるのはどんな瞬間？
- 求人票を見ただけでは分からないことは？
- 新人に1つだけアドバイスするとしたら？

## 5. AI活用の方針

AI自体が目的ではなく、口コミデータを**使いやすくする手段**として位置づける。

1. **意味検索**：自然文の希望条件から近い口コミ・店舗を検索
2. **口コミ分析**：企業向けに良い点／改善点／頻出意見を要約
3. **将来のRAG拡張**：口コミ・求人・企業情報を横断検索して回答生成（MVP対象外）

## 6. 非機能要件（要点）

- **UX**：「アンケートに答えている」感覚ではなく「経験を共有している」感覚を重視
- **レスポンシブ**：スマホ利用を最優先
- **セキュリティ**：認証方式とアプリ内ユーザー管理を分離し、ロールベースでアクセス制御する。他人の投稿は編集不可、入力値を検証する
- **プライバシー**：投稿者個人を特定しにくい表示形式
- **信頼性**：ハッカソンでは最低限の投稿ルール定義に留め、投稿者認証や通報機能等は将来対応

## 7. MVPスコープ

| 区分 | 内容 |
|---|---|
| ✅ 必須 | 開発用Basic認証／テストユーザー切替／店舗一覧／店舗詳細／口コミ閲覧／口コミ投稿 |
| 🔺 優先度高 | 店舗検索／プロフィール／企業向け簡易ダッシュボード／評価集計 |
| 🚀 技術チャレンジ | 自然言語検索／口コミ意味検索／AI傾向分析 |
| ❌ 対象外 | ネイティブアプリ、DM/チャット、求人応募・採用管理、決済、画像投稿、本格RAG・レコメンド・モデレーション 等 |

## 8. 成功条件

- **求職者**：店舗詳細を見て「実際に働いたときの様子」が求人票より想像できる
- **投稿者**：アンケートではなく経験の共有だと感じられる
- **企業**：評価点と課題を短時間で把握できる
- **技術**：AIを非構造化データ（口コミ）の検索・分析に実質的に活用できている

## 9. 価値の中心

星評価ではなく「実際に働いたらどうなるか」を伝えることが本サービスの核。

> 求人票：「研修制度あり」
> 口コミ：「最初の3日は先輩が横についてくれる／忙しい日は質問しづらい」
