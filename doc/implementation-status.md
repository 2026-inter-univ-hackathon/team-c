# 実装状況

2026-09-21時点の `feature/review-flow-redesign` 作業ツリーに基づく。公開環境への反映を意味しない。

## 実装済み

- PostgreSQL / Drizzleのスキーマ、マイグレーション、開発用seed。約50店舗と新仕様のダミー口コミ10件
- 店舗の検索・絞り込み・並べ替え・ページング、店舗詳細、端末内のお気に入り
- 口コミ投稿の全5ステップ（属性、特徴タグ、4項目評価、生の声、公開プレビューとガイドライン同意）
- 投稿のサーバー側検証、1ユーザー・1店舗の一意制約、同意したガイドラインの版とサーバー日時の保存
- 4項目平均による口コミ総合点、その口コミ総合点の平均による店舗総合点。丸めは表示時のみ。おすすめ度は点数に含めない
- 公開口コミでの属性バッジ、勤務期間、投稿時点の在籍状況、特徴タグ、4項目評価、短文。投稿日は上旬・中旬・下旬に曖昧化
- 開発用DBで明示的に有効化した場合のみ、固定テストユーザーで投稿。固定ユーザーの投稿だけを消す開発用コマンド
- GitHub Actionsによるテスト・型・Lint・整形・Build・DB準備・依存監査の設定（実行結果は別途確認）

投稿・DB更新の手順は [新しい口コミ投稿フローの開発手順](./review-flow-development.md)、詳細仕様は [口コミ投稿フロー再設計](./review-flow-redesign.md) を参照する。

## 取得と公開範囲

RouteのServer FunctionからUse Case、Repositoryを経由してDBへアクセスする。有効な店舗と公開可能な新形式の口コミのみを返す。口コミの内部投稿者ID、正確な投稿日、ガイドライン同意日時は公開レスポンスに含めない。

## 未実装・残作業

- 認証、セッション、権限制御。通常の公開環境では認証導入まで口コミ投稿を受け付けない
- 口コミ編集、プロフィール、組織管理、お気に入りの端末間同期
- ベクトル検索。コスト面の判断により対象外
- 口コミが3件以上ある店舗のレーダーチャート。後続で検討する
- 大規模データでの店舗集計・検索性能の検証

## 検証

単体テストでは必須項目と境界値、同意なしの直接POST相当の入力、公開環境での投稿拒否、1ユーザー・1店舗の制約、総合点の計算を確認する。開発DBでは実際の投稿・重複投稿・リセット対象の限定と、公開レスポンスに内部IDや正確な日時が含まれないことを確認する。最終的なLint・型チェック・既存テスト・Buildの結果は作業報告に記載する。
