# 一般ユーザー向け機能

## 画面

| URL | 機能 |
| --- | --- |
| `/` | 店舗名・エリア検索、業種からの検索、使い方 |
| `/stores` | 検索、業種・エリア・最低評価の絞り込み、並べ替え、ページング |
| `/stores/$storeId` | 店舗情報、平均・評価軸別スコア、口コミ・質問回答 |
| `/saved` | このブラウザに保存した職場の一覧、解除・全解除 |
| `/stores/$storeId/reviews/new` | 開発環境限定の固定テストユーザーによる5ステップ口コミ投稿 |

検索・お気に入りの取得APIは読み取り専用です。口コミ投稿は認証導入まで、開発用DBで明示的に有効化した固定テストユーザーに限定します。公開環境では投稿を拒否します。お気に入りの保存対象は店舗IDのみで、最大100件、ブラウザごとの保存です。

## 検索仕様

- 店舗名は部分一致、エリアは都道府県または市区町村の部分一致。複数条件はANDです。
- 業種は有効なカテゴリのみ、最低評価は0〜5の範囲です。
- 並び順は店舗名・平均評価・口コミ件数。評価のない職場は評価順で最後になります。同順位は名前・IDで順序を固定します。
- 12件単位で表示し、範囲外のページは最後のページに補正します。口コミは10件単位です。
- 検索条件はURLに保持し、再読み込み・戻る操作で再現できます。お気に入りのIDはページURLから受け取りません。
- SQLの `%`・`_` は検索文字としてエスケープし、ユーザー入力をSQLに連結しません。
- 非公開・削除済み店舗は保存一覧でも表示しません。表示できない保存項目も「保存をすべて解除」で消せます。

## デザイン

`#FF6A2B` を主要操作とアクセント、`#75402A` を見出し・情報の強調、`#FFCAB3` を補助背景に使用します。白・暖色の背景と組み合わせ、PCでは条件サイドバー、スマートフォンでは縦並びにします。

[OpenWorkの評価・口コミの構成](https://www.openwork.jp/company_answer.php?m_id=a0C1000000yRvqf)と[食べログのエリア・ジャンル検索](https://tabelog.com/rstLst/RC/)を参考に、独自の画面を作成しています。画像は既存の `img/` を再利用し、実店舗の写真と誤認されないよう「業種イメージ」を表示します。

## 実装ファイル

- `src/routes/`: 画面とURL状態、loader
- `src/components/site-shell.tsx`, `icon.tsx`: 共通ヘッダー・フッターとアイコン
- `src/features/stores/`: 検索フォーム、店舗カード、端末内保存
- `src/schemas/store-search.ts`: 検索入力のZod検証
- `src/server/store-functions.ts`: 読み取り専用Server Functions、汎用エラーへの変換
- `src/server/use-cases/stores/search-stores.ts`: 入力検証と検索呼び出し
- `src/server/repositories/search-stores.ts`: DB全体の検索・集計・ページング
- `src/styles.css`: 配色、レイアウト、レスポンシブ表示

## 確認手順

開発DBを準備して `pnpm dev` で起動します。自動検証は `pnpm run test`、`typecheck`、`lint`、`format`、`build` です。

1. トップの検索から店舗一覧へ進み、店舗名・市区町村・業種・最低評価を変更する。
2. 条件付きURLを再読み込みし、条件と結果が維持されることを確認する。
3. 並べ替え、結果0件、複数ページがある場合の前後移動を確認する。
4. ハートを押して保存一覧に進み、再読み込み後も残ることを確認する。
5. 保存解除と全解除、ブラウザで保存を禁止した場合の失敗メッセージを確認する。
6. 店舗詳細の口コミ・質問回答を開き、不正IDと存在しないIDで不存在画面を確認する。
7. スマートフォン幅、キーボード操作、画像・長い口コミの折り返しを確認する。

投稿APIとDBスキーマを含むためVCAL-2として、人間の詳細レビュー対象です。公開条件、投稿の環境制限、入力検証、エラー時の情報非開示、検索集計の負荷を重点確認してください。認証と新しい依存関係は追加していません。
