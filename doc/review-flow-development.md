# 新しい口コミ投稿フローの開発手順

仕様は [review-flow-redesign.md](./review-flow-redesign.md) を参照する。投稿と口コミリアクションは認証導入前の開発機能であり、通常環境からの更新はサーバー側で拒否する。

## 開発DBの確認

DBへ変更を加える前に、`pnpm run db:check-dev` を実行する。このスクリプトは接続先ホスト・DB名・開発フラグの状態のみを表示し、接続文字列・パスワードは出力しない。

接続先が開発用DBであることを、ホストとDB名の両方で確認する。確認できないDBではマイグレーション・seed・リセットを実行しない。Gitブランチの変更はDB内容を戻さない。

## 明示的な開発設定

`.env` に次の設定を追加する。秘密情報は表示したりコミットしたりしない。

```dotenv
DEV_DATABASE_NAME=team_c_dev
ENABLE_DEV_REVIEW_POSTING=true
```

`DEV_DATABASE_NAME` は実際の開発DB名と完全一致させる。名称には `dev`、`test`、`local` のいずれかを含める。アプリ側では `NODE_ENV=development`、上記フラグ、接続先DB名の一致をすべて要求する。投稿者IDはサーバー内の固定テストユーザーから決め、リクエストの `userId` は受け付けない。

CLIでseedやリセットを実行するときも `NODE_ENV=development` を明示する。共有DBでは同じテストユーザーの1店舗1件枠を共有する。

## DB更新とseed

1. 読み取り専用のDB確認を行う。
2. `NODE_ENV=development pnpm run db:prepare-review-flow` で旧ダミー口コミの件数を確認する。
3. 対象DB・件数を確認後、`NODE_ENV=development pnpm run db:prepare-review-flow -- --execute` で旧ダミー口コミを削除する。
4. `pnpm run db:migrate` で新規マイグレーションを適用する。
5. `NODE_ENV=development pnpm run db:seed` で、50店舗に新形式のダミー口コミを計32件投入する。

seedは開発DB名と明示フラグを確認し、固定テストユーザーの投稿を残して旧ダミー口コミを新形式に入れ替える。初回は既存口コミを削除するため、接続先の確認が必須。旧形式の口コミは公開一覧に出さない。認証済み投稿者への差し替えは後続作業。

## 固定テストユーザーの投稿リセット

`NODE_ENV=development pnpm run db:reset-test-reviews` は対象件数を表示するだけ。確認後、`NODE_ENV=development pnpm run db:reset-test-reviews -- --execute` で固定ユーザーの口コミのみ削除する。紐づく評価・回答も同じトランザクションで削除する。ダミー投稿者の口コミ、店舗、ユーザーは残す。

## 表示と評価

公開口コミには属性バッジ、勤務期間の区分、投稿時点の在籍状況、タグ、4評価、おすすめ度、短文を表示する。口コミが5件未満の店舗では属性を大まかにし、勤務期間を隠して投稿日を年月までに丸める。5件以上では投稿日を日本時間の上旬・中旬・下旬に丸める。内部投稿者IDや正確な日時、ガイドライン同意日時は公開レスポンスに含めない。

口コミ総合点は4評価の算術平均。店舗の評価軸別・総合点は勤続期間と在籍状況を掛け合わせた重み付き平均で、小数第1位へ丸めて保存する。評価順は口コミが少ない店舗を全体平均へ寄せるベイズ補正値を使う。おすすめ度は点数に含めない。

生の声は30〜300文字で、設問、補足説明、書き方のヒント、入力中も残る記入例を表示する。クライアントとサーバーは前後の空白を除いたUnicodeコードポイント単位で文字数を検証し、禁止語も確認する。

## 現在の検証

変更後はTest、Lint、Format、型チェック、Buildのほか、開発DBで投稿・重複投稿・同意拒否・リアクション・リセット対象の限定を確認する。接続先が開発DBと確定できない場合はDB変更とブラウザの投稿確認を保留し、その理由を報告する。
