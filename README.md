# バイトのホンネ

働いた人の声から、求人票だけでは分からない職場の雰囲気や働きやすさを比較する口コミWebアプリです。

## 何を作ったか

店舗名・エリア・業種・最低評価で職場を探し、4つの評価軸と実体験の口コミを見比べられます。口コミには投稿時点の在籍状況、立場、勤務期間、職場の特徴を付け、正確な投稿日や内部ユーザーIDは公開しません。口コミが少ない店舗では投稿者属性をおおまかに表示し、誰が書いたか特定されにくくしています。

評価軸は「職場の雰囲気」「教育・フォロー体制」「業務のゆとり」「シフトの融通度」です。個々の口コミ総合点は4項目の算術平均です。店舗の評価は、勤続期間と投稿時点の在籍状況を重みとして公開口コミを集計し、評価順では口コミが少ない店舗を全体平均へ寄せるベイズ補正値を使用します。おすすめ度は点数へ含めず、旧プロトタイプの「参考度 高／中／低」は表示しません。

## 現在の実装状況

2026-09-23時点の `main` には、次の機能があります。

- トップ、店舗検索、店舗詳細、このブラウザに保存した職場、口コミ投稿、ガイドライン・利用規約等の案内画面
- 店舗名・エリア検索、業種・最低評価の絞り込み、店舗名・評価・口コミ件数による並べ替え
- 検索条件のURL保持、店舗12件・口コミ10件単位のページング
- 4評価軸、投稿者属性、特徴タグ、おすすめ度、生の声を含む公開口コミ
- 店舗IDだけを `localStorage` に保持する「気になる」保存（最大100件）
- 開発環境限定の5ステップ口コミ投稿と、固定テストユーザーによる口コミリアクション
- PostgreSQL / Drizzleのスキーマ・マイグレーション・seed、GitHub ActionsのCI、開発デモへの自動デプロイ

認証・セッション・認可、通常環境での口コミ投稿、口コミ編集・削除、プロフィール、組織向け管理画面、端末間のお気に入り同期、AI検索・AI要約は未実装です。口コミ投稿とリアクションは、明示的に許可したローカル開発DBでのみ固定テストユーザーとして実行できます。

詳細は[実装状況](doc/implementation-status.md)、操作と検索仕様は[一般ユーザー向け機能](doc/public-user-features.md)を参照してください。

## 現在の利用動線

```text
① 店舗名・エリア・業種・最低評価で職場を探す
      ↓
② 評価、口コミ件数、業種イメージを一覧で比較する
      ↓
③ 店舗詳細で4評価軸、投稿者の背景、生の声を読む
      ↓
④ 必要なら「気になる」へ保存し、自分で候補を比較する
      ↓
⑤ 開発環境では、5ステップのフォームから口コミを投稿する
```

旧プロトタイプは [`legacy/index.html`](legacy/index.html) に残していますが、現在のTanStack Start版とは機能・評価方法・操作が異なります。

## AI に任せなかった部分

現在のMVPには、外部AI API、AI検索、AI要約、AIレコメンドを組み込んでいません。アプリが行うのは、入力された条件での検索、コードで定義した重みによる評価集計、口コミと投稿者背景の表示です。どの評価軸や口コミを重視するか、どの職場を候補に残すか、最終的に応募するかは利用者が判断します。

「気になる」は利用者自身が候補を保存する機能であり、アプリやAIによる採用・却下判定ではありません。将来AI要約を追加する場合も、元の口コミを確認できる補助機能として設計し、自動的な応募判断には使用しません。

開発ではAI支援を利用していますが、仕様決定、セキュリティ境界、レビュー、テスト結果の確認、マージ判断は人が行っています。

## どう開発したか

**9/4 にやったこと**

- 前半は **ペアプログラミング**（ドライバーとナビの2人で書き、10分で交代）
- 交代のたびに `CLAUDE.md` の「申し送り」を書き換えて、設計がぶれないようにした
- 後半は役割を固定して仕上げ。レビュー項目を「属性 / 事実 / 5段階評価」の3種類に分ける設計を先に決め、そのあとに画面を作った

**開発期間（9/5〜9/24）にやったこと**

- 機能ごとにブランチを切り、PRで差分とCI結果を確認してから `main` へマージした
- 旧静的プロトタイプをTanStack Startへ移行し、店舗検索・詳細・保存・5ステップ口コミ投稿を実装した
- PostgreSQL / Drizzleを導入し、RouteからUse Case、Repositoryを経由してDBへアクセスする構成に整理した
- 詰まったときは関連コード・設計書・既存テストを確認し、変更範囲を小さく分けてテストと文書を一緒に更新した
- Test、Lint、Format、型検査、Build、DB検証をCIへ組み込み、成功した最新の `main` を開発デモへ自動反映した

## 動かし方

Node.jsと、`package.json` の `packageManager` に指定されたpnpmを用意してください。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

開発サーバーは <http://localhost:3000> で起動します。トップページはDBなしでも表示できますが、店舗一覧・詳細にはPostgreSQL 18が必要です。

店舗機能を確認する場合は、プロジェクト直下の `.env` に開発DBの `DATABASE_URL` を設定します。接続情報はコミットせず、チャットやログにも貼り付けないでください。

```bash
pnpm run db:check-dev
pnpm run db:migrate
```

seedと口コミ投稿を有効にするには、ローカル開発DBに対して `DEV_DATABASE_NAME` と `ENABLE_DEV_REVIEW_POSTING=true` も必要です。

```bash
NODE_ENV=development pnpm run db:seed
pnpm dev
```

安全条件とデータ更新手順は[口コミ投稿フローの開発手順](doc/review-flow-development.md)を参照してください。

## 検証コマンド

```bash
pnpm run test
pnpm run lint
pnpm run format
pnpm run typecheck
pnpm run build
```

CIでは上記に加え、PostgreSQL 18へのマイグレーション、seedの再実行、スキーマとマイグレーションの差分、High以上の依存関係脆弱性を確認します。E2Eテストは未導入です。

旧静的プロトタイプは [GitHub Pages](https://2026-inter-univ-hackathon.github.io/team-c/) で確認できます。これは現在のTanStack Start版ではありません。
